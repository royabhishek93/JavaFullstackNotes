Deep Dive

Where engineers get it wrong

  • Trap 1: Hand-rolling retry/circuit-breaker per service → 20 inconsistent, under-tested implementations.
  • Trap 2: Assuming control-plane outage = mesh outage. Sidecars keep serving on last-known config.
  • Trap 3: Treating the mesh as "free" — ignoring the 1-3ms/hop + 40-100MB/pod cost.
  • Trap 4: Adopting Istio at 3-4 services, low fan-out — ops complexity not yet justified.
  • Trap 5: Treating gateway & mesh as substitutes — gateway ≠ internal retries; mesh ≠ external rate limiting.
  • Trap 6: In-memory rate limits (not Redis-backed) → inconsistent limits once you scale to 2+ gateway replicas.
