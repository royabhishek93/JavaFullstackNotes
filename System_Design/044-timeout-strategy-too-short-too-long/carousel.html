TRAP #16 / 10
Deep Dive — Trap #2, #3

Timeout alone isn't enough

50% of last 10 calls timeout
→
Circuit OPENS
stop calling

Bulkhead: limit threads blocked on any one downstream.

Retry + Jitter: retry once/twice with backoff after timeout — never immediately.

Trap: one-size-fits-all timeout. Fraud scoring needs 500ms (skip if slow). S3 upload needs 30–120s. Same value for both breaks one of them.

Decision Tree + Interview Answer

How to pick the right timeout

What's P99 latency of downstream?
Known →
timeout = P99 + 50%
Unknown →
measure first, never guess

"Too short a timeout causes false positives — healthy services look dead. Too long causes cascade — slow services exhaust your thread pool. Right timeout = P99 + buffer. Pair it with circuit breaker so when timeouts are frequent, you stop calling the service and return a fallback."
