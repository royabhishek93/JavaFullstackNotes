EFS costs 13 times more than S3 for the exact same gigabyte. Store user photos as BLOBs in Postgres instead, and your 20-minute backup becomes a 14-hour one. Pick the wrong storage type and you don't just overpay — you break backups.

Object Storage (S3)

The Postal Warehouse

key → blob

Ship a package, get a tracking number, retrieve the whole thing by key over HTTP. No partial writes. Replicated across 3+ AZs, 11 nines durability, $0.023/GB/month.

Best for: user uploads, videos, images, backups, data lake, CDN origin.

Block Storage (EBS)

The Laptop Hard Drive

1 EC2 instance

Network-attached SSD that behaves like a local disk — fseek, fwrite, partial writes, POSIX filesystem. Sub-millisecond latency, up to 64,000 IOPS (io2), snapshots to S3.

Best for: MySQL/Postgres data files, OS root volumes, transactional workloads on one machine.

File Storage (EFS / NFS)

The Shared Network Drive

EC2 #2

/app/data

Multiple servers mount the SAME directory at the SAME time over NFS. Changes are instantly visible to every mounted instance. $0.30/GB/month.

Best for: shared configs, ML training data, WordPress media, CI/CD artifacts.

Trap 1: Blobs in the Database

The #1 Junior Mistake

✕ Storing photos/PDFs/attachments as BYTEA/BLOB columns in Postgres or MySQL — every backup and every replica now has to move that binary data too.

✓ Fix: store bytes in S3, store the URL/key in the database row.

"S3 holds the bytes, the database holds the address — never store binary files in a relational database."

Trap 2: Wrong Tool for the Scale

EBS for Video, EFS Instead of S3

1 EBS volume
✕
100K viewers

EBS is attached to ONE instance — it cannot fan out to thousands of concurrent video viewers. And reaching for EFS when you just need "store + fetch by key" costs 13x what S3 would.

Fix: pre-signed URL uploads straight to S3 — your backend never proxies file bytes.

Interview Scenario: OTT Video Platform

Architect's Answer

Client uploads via a pre-signed URL → lands in S3 → event → transcoding job produces HLS segments (480p/720p/1080p) → also stored in S3 → CloudFront (CDN) serves from S3 origin.

User accounts, subscriptions, view history → Postgres on EBS (fast random reads, single-machine transactional workload).

✕ Never EBS for video bytes   ✕ Never EFS — 10x the cost, no benefit here.

Decision Tree & Interview Answer

Quick Reference

Fetched by URL, no partial writes, cost-sensitive? → S3. Database data files, single machine, low latency? → EBS. Multiple servers need the SAME filesystem live? → EFS.

"Object storage is for files you access by URL — S3 is cheap, unlimited, HTTP. Block storage is for databases — attached to one machine, fast random I/O. File storage is for shared filesystems — multiple servers, same directory. For user uploads and videos: always S3."
