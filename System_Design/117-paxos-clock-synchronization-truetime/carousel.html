01 · THE HOOKPaxos + TrueTime
The Problem

No two clocks are ever perfectly in sync

commits txn A
Server: US

If B's server clock is slightly fast or A's is slightly slow, B (which happened after) can get a smaller timestamp than A. History appears to run backwards.

03 · PAXOS BASICSPrepare/Promise → Accept
Trap

Dueling proposers can livelock Paxos

Proposer A
#7
⇄
Proposer B
#8

Acceptors must always obey the higher-numbered promise. A's Phase 2 can fail right after its Phase 1 succeeded, because B's higher proposal snuck in between.

A retries with #9, B retries with #10 ... with no elected leader, this can repeat forever — nothing is ever fully agreed.

Fix used in practice: layer leader election on top → Multi-Paxos, which converges toward Raft's model.

04 · ANTI-PATTERNNo leader = livelock risk

Same safety guarantees — Raft trades Paxos's generality for a single-leader rule that's dramatically easier to implement & review. That's why it won: etcd, Consul.

earliest = 100.001s

TT.now() = [earliest, latest] — roughly a 5ms window, kept tight via GPS + atomic clock references in every data center.

06 · TRUETIMEHonest uncertainty
Scenario 4

Commit-wait: buy certainty with latency

1. Pick s = TT.now().latest
→
2. WAIT until earliest > s
→
3. Release locks, ACK

Result: any transaction that starts after this commit is ACKNOWLEDGED anywhere is guaranteed a larger timestamp — external consistency, globally, with no shared clock.

Cost: added latency ≈ the uncertainty window, paid on every write transaction.

07 · COMMIT-WAITSpanner's core trick
Scenario 5

Hybrid Logical Clock: no GPS required

1719850000123,0
→
1719850000123,1

HLC = (physical_time, logical_counter). On receive: physical = max(own, received); logical resets to 0, or +1 if physical time didn't advance — breaks ties within the same millisecond.

O(1) comparison cost, no GPS/atomic clocks — looser guarantee than TrueTime, used by CockroachDB & YugabyteDB.

09 · COMPARISONPick by guarantee, not hype
Interview Cheat Sheet

Decision tree + the answer to say out loud

Need global write ordering across regions?
No leader ok, need simplicity → Raft (etcd/Consul)
Have GPS/atomic clocks → TrueTime + commit-wait
No special hardware → Hybrid Logical Clock (CockroachDB)
"TrueTime returns an interval bounded to a few ms using GPS/atomic clocks. Commit-wait pauses until the earliest bound passes the commit timestamp — so any later transaction is guaranteed a larger one. Without that hardware, I'd use a Hybrid Logical Clock instead — cheaper, looser causal ordering."
