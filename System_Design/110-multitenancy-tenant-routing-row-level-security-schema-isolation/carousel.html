The Problem

8,000 tenants. One database. Zero room for error.

One shared floor. Thousands of tenants packed in.
One forgotten WHERE tenant_id = ? or one query storm from a single tenant, and the whole floor feels it.

  • Leak risk A bug in one query path exposes another tenant's data
  • Noisy neighbor One tenant's heavy query degrades everyone sharing the instance
Tier 1 · 8,000 small tenants

Shared Schema + Row-Level Security

orders table
every row tagged tenant_id

Postgres policy auto-rewrites every query:
... AND tenant_id = current_setting('app.tenant_id')

  • Cheapest, highest density — thousands of tenants per instance
  • Belt-and-suspenders: Hibernate @Filter at app layer + RLS policy at DB layer
  • Trap table owners bypass RLS unless you run FORCE ROW LEVEL SECURITY
Tier 2 · 200 mid-size tenants

Schema-per-Tenant

tenant_acme.orders
tenant_globex.orders
tenant_initech.orders

One Postgres instance · N schemas · same building, separate locked floors

  • Routed via AbstractRoutingDataSource or SET search_path TO tenant_acme, public
  • Cross-schema query requires explicit schema-qualified SQL — accidental leakage structurally harder
  • Limit ~1,000–2,000 schemas/instance before catalog bloat (pg_class, pg_attribute)
  • Trap PgBouncer transaction-pooling needs search_path reset per transaction
Tier 3 · 5 enterprise tenants

Database-per-Tenant

db-acme-corp
db-globex-inc
db-healthco
(region-pinned)

Each an entirely separate building: own connections, own storage,
own backup/restore, own failover.

  • Total physical isolation — no shared connection pool, no shared query planner
  • Right when contract, regulation, or scale demands it — e.g. HIPAA data-residency for a healthcare tenant
  • Cost highest $/tenant — don't use this for 12 small customers

Deep Dive — Failure Modes

Where Engineers Get It Wrong

Failure Mode 1 The Forgotten Policy

New table shipped without ENABLE ROW LEVEL SECURITY + CREATE POLICY. RLS is off by default — any session sees every tenant's rows.

Fix CI check fails build if a tenant table lacks an RLS policy; CREATE TABLE + ENABLE RLS ship as one atomic reviewed unit.

Failure Mode 2 Noisy Neighbor

BigCorp runs a 40-second full-table-scan report hourly. Every other tenant's p99 latency: 80ms → 3–4 sec

Fix Bulkhead pattern (cap connection pool per tenant) + per-tenant rate limiting keyed by tenant_id.
