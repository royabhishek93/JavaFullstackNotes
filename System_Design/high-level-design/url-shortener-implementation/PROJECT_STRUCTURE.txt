🎯 Core Features Implemented

   - Rate limiting
   - URL validation
   - Security checks
   - Duplicate detection
   - Custom aliases
   - Expiration support

2. ✅ URL Redirection
   - Multi-layer caching (L1/L2/L3)

   - Expiration checking
   - 301/302 redirects

3. ✅ Short Code Generation
   - Snowflake algorithm (distributed)
   - Redis counter (atomic)
   - Base62 encoding
   - Collision handling

4. ✅ Caching Strategy
   - L1: Caffeine (10K entries, 5 min TTL)
   - L2: Redis (1 hour TTL)
   - L3: Database fallback
   - Cache statistics


📈 Performance Characteristics
-------------------------------

Latency Targets:
  • URL Creation: < 200ms (p99)
  • URL Redirect: < 100ms (p99)
    - L1 cache hit: ~1ms
    - L2 cache hit: ~5ms
    - DB fallback: ~50ms

Throughput:
  • Creation: 5,000 req/sec per instance
  • Redirect: 500,000 req/sec (with CDN)

Cache Hit Rates:
  • L1 (Caffeine): 70-80%
  • L2 (Redis): 15-20%
  • L3 (Database): 5-10%


🏗️ Design Patterns Used
-------------------------

1. Strategy Pattern      - Multiple short code generators
2. Repository Pattern    - Data access abstraction
3. Service Layer Pattern - Business logic separation
4. Builder Pattern       - Entity/DTO construction
5. Template Method       - Multi-layer cache hierarchy
6. Facade Pattern        - Service layer simplification


💾 Database Schema
------------------

PostgreSQL (url_mappings):
  • id (BIGSERIAL PRIMARY KEY)
  • short_code (VARCHAR(10) UNIQUE)
  • long_url (TEXT)
  • user_id (BIGINT)
  • created_at (TIMESTAMP)
  • expires_at (TIMESTAMP)
  • is_custom_alias (BOOLEAN)
  • status (VARCHAR - ACTIVE/EXPIRED/DELETED)
  • click_count (BIGINT)
  
  Indexes:
  - idx_short_code (unique)
  - idx_user_id
  - idx_created_at
  - idx_expires_at
