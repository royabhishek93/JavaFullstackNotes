Nested-Loop Intersection Is Slow

The Problem

"system" → [3,7,19,42,100]. "design" → [7,19,55,100,300]. Naive nested loop checking every pair: O(n×m) — brutal for million-entry lists.

Two-Pointer Sorted Merge

The Solution

Walk both sorted lists once. Equal → match, advance both. Smaller → advance only that pointer. O(n+m), touches each element once.

Result for the example above: [7, 19, 100].

Skip Pointers

Accelerating Long Lists

A common term like "the" might have billions of entries. Skip pointers every ~√n entries let you JUMP ahead instead of stepping one at a time.

10M entries: ~3,000 jumps instead of up to 10M sequential steps.

Scatter-Gather

Across Sharded Index

Shard 2

Coordinator scatters query to all shards, each does local intersection + top-K, coordinator gathers + merges.

Response time = MAX(all shards), not average.

The Fix

Hedged Requests + Replicas

If a shard's primary exceeds its own p95 threshold, fire the same request to a replica concurrently — take whichever responds first.

Small duplicate work cost, large p99 latency reduction.

Quick Reference

Index fits on 1 node? → Skip scatter-gather entirely. Sharded at scale? → Add replica shards + hedged requests, non-negotiable.
