BM25 scans for the literal words "affordable", "wireless", "earbuds." None match → ✕ zero results. Not wrong — just no concept of meaning.

Vector knows "affordable" ≈ "budget" ≈ "cheap", "earbuds" ≈ "headphones" ≈ "in-ear." Zero words match but ✓ hundreds of relevant products found.

Production answer: use both. BM25 for precision on exact terms, Vector for recall on semantics, fused by a ranking algorithm.

BM25 — The Scoring Formula

IDF (rarity) × TF Saturation (frequency)

BM25(doc,query) = Σ IDF(term) × TF_norm(term,doc)
IDF = log((N-df+0.5)/(df+0.5)+1)
"photovoltaic" df=100 → IDF=9.2 (rare, HIGH)
"the" df=999K → IDF≈0.0 (common, LOW)
TF_norm = TF×(k1+1) / (TF + k1×(1-b+b×|doc|/avgdl))
k1=1.2 saturation · b=0.75 length norm

Example — "cheap flights" (N=1M docs): IDF(cheap)=4.6, IDF(flights)=2.3

DocContentScore

B500-word post, cheap×3, flights×5≈ 5.5 (saturated + length-penalized)

Hybrid Search — Reciprocal Rank Fusion

Best of BM25 Precision + Vector Recall

Query: "buy iPhone 15 case" — BM25 misses synonyms, Vector misses model specificity.

RRF_score(doc) = Σ 1/(rank_in_list + k), k=60

Real-World Appearances

Where This Pattern Shows Up

SystemSearch Pattern
E-CommerceBM25 for exact SKU/brand. Vector for "camping in cold weather." Hybrid for general discovery.
Proximity SearchBM25 on cuisine/name + vector on review text + geo_distance filter, single ES query.
Email (Gmail-like)BM25 for sender/subject/keyword. Vector for "Q3 budget meeting" ≈ "Q3 finance discussion."
RAG / LLM retrievalVector = retrieval step: query→embed→kNN→top-K chunks→LLM context. BM25 hybrid improves precision.

Don't use vector search when: exact-identifier lookup (IDs/SKUs), catalog <10K docs (overhead not worth it), or freshness is critical (embeddings lag behind BM25 index updates).

Decision Tree & Interview Answer

The Architect's One-Liner

  • User types exact identifier/code? → BM25
  • User describes intent in their own words? → Vector
  • Catalog vocabulary ≠ user vocabulary? → Vector or synonym expansion
  • Need both precision and recall? → Hybrid + RRF (k=60)
  • Small catalog, tight freshness SLA? → BM25 only
"BM25 matches keywords, vector search matches meaning — use hybrid search with RRF fusion to get exact matches first and semantic fallback when keywords fail."

Overhead: ~8ms hybrid latency. When justified: any catalog where users don't type your exact vocabulary.
