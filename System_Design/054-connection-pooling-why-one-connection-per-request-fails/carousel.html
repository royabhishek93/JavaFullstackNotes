Connection Pooling

Slide 1 / 10 — The Hook

151 → 0.1s

A raw DB connection costs 50–150ms (TCP + TLS + auth) before any query runs. MySQL's default max_connections is 151 — open one connection per HTTP request at 1,000 req/sec, and you blow through that limit in a tenth of a second — "Too many connections," app down.

Bug: The Connection Leak

The #1 Production Killer

An early-return path forgets to release the connection. The pool drains silently over hours — getConnection() gets slower and slower until a restart "fixes" it (until next time).

Fix: always use try-with-resources — the connection auto-returns to the pool the instant the block exits, no matter how it's left.

Bug: Held Transactions & Fleet Sprawl

Two More Traps

Held connection: calling an external API mid-transaction holds a scarce pool slot hostage for the whole call — finish DB work, release, THEN call out.

Fleet mismatch: 3 services × pool=50 = 150 connections vs MySQL's 151 limit. One more instance anywhere → crash. Nobody tracked the total centrally.
