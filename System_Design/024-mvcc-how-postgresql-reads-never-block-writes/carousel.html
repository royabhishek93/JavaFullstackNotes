xmin / xmax Row Versioning

The Solution

Writes never edit in place — they create a NEW row version. Old version gets xmax stamped, stays visible to older snapshots.

Txn 150 (started before commit) reads "Alice". Txn 250 (started after) reads "Alicia". Neither blocked.

Snapshot Isolation

Same Row, Different Correct Views

Txn A's snapshot taken at t=0 doesn't include a write at t=1 → sees OLD value.

Txn B's snapshot taken at t=3 includes that write → sees NEW value. Same row, same moment, two consistent views.

VACUUM & Table Bloat

The Cost Isn't Free

Dead row versions pile up on disk — can double or triple table size. VACUUM marks them reusable but does NOT shrink the file.

VACUUM FULL reclaims space but takes a full table lock — maintenance-window only.

XID Wraparound

The Bug That Can Take Your DB Offline

32-bit XID counter wraps every ~49 days at 1,000 TPS. Wraparound risks silent, catastrophic data loss.

✓ Alert at age > 150M   ✕ At 2B, PostgreSQL forces read-only mode.

Dead entries also bloat B-tree indexes — fix online with REINDEX INDEX CONCURRENTLY (no table lock).

Write Skew — The Doctor On-Call Bug

What MVCC Can't Catch

Doctor A checks "is B on-call?" → yes → goes off-call. Doctor B checks "is A on-call?" → yes → goes off-call. Zero doctors on-call. MVCC saw no conflict.

Fix: SERIALIZABLE isolation — PostgreSQL's SSI detects the cycle and aborts one transaction.
