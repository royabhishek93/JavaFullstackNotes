The Problem

1 Billion Restaurants. "Find within 5km."
Why does your database choke?

SELECT * FROM restaurants WHERE latitude BETWEEN 40.7 AND 40.8 AND longitude BETWEEN -74.0 AND -73.9; -- looks fine... but at 1B rows it's a disaster

A B-tree understands 1 dimension. The moment you add a second AND longitude BETWEEN... the engine scans the whole latitude range, then filters — for 1B rows that's a seq-scan-shaped disaster.

FIX  Collapse 2D coordinates into 1D while preserving proximity → Geohash (fixed grid string) or QuadTree (adaptive recursive split).

World → 32 cells (base-32 of interleaved lat/lng bits) → each cell → 32 sub-cells (append 1 char) → repeat. Nearby places share a common prefix.

Critical Edge Case

The 9-Neighbor Problem

A restaurant just 10 meters away can sit in a different geohash cell if it's across a border. Querying only your own cell silently drops real neighbors.

RULE  Always query the center cell + all 8 neighbors = 9 total prefixes. Never query the center cell alone.

WHERE geohash LIKE 'dr5re%' -- center OR geohash LIKE 'dr5rf%' -- E OR geohash LIKE 'dr5rd%' -- W OR geohash LIKE 'dr5rg%' -- N OR geohash LIKE 'dr5rs%' -- S ...+4 diagonals = 9 queries

QuadTree

Adaptive Recursive Splitting

Split a quadrant into 4 only when it holds more than MAX_CAPACITY points. Dense areas split deep; empty areas stay one giant leaf.

static final int MAX_CAPACITY = 50; void insert(Restaurant r){ if (children != null) { getQuadrant(r).insert(r); return; } restaurants.add(r); if (restaurants.size() > MAX_CAPACITY) split(); }

Which One Do You Reach For?

YES → In-memory QuadTree (adaptive, <1ms) NO → Already on PostgreSQL? YES → PostGIS GiST (ST_DWithin) NO → Geohash column + B-tree index Sharding the DB itself by geography? "B-tree indexes are 1D — they can't answer spatial queries; we collapse 2D coordinates into a geohash string so standard indexed prefix lookups give us geographic proximity search, or we use a QuadTree to adaptively partition dense areas like city centers into smaller cells than sparse areas like deserts."
