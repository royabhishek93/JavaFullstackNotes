Files Table + Blobs Table

Data Model

files(file_id, user_id, filename, content_hash)

blobs(content_hash, size_bytes, ref_count)

3 files can point at the SAME content_hash — physical bytes stored once.

Chunked CAS

Small Edits, Small Uploads

1GB file = 256 × 4MB chunks, each hashed independently. Edit 1 chunk → upload only that 4MB, the other 255 stay untouched.

Reference Counting

The Trap Nobody Remembers

Deleting a file ≠ deleting the blob — other users may still reference it.

ref_count: 3 → 2 (Alice deletes) → still 2 users share the blob. Only ref_count = 0 triggers actual deletion.

Verify Ownership, Not Just Existence

Security Trap

Blobs are shared by design — a user can't guess another's SHA-256 hash (astronomically unlikely), but you must still check they OWN a metadata record pointing at that blob before serving it.
