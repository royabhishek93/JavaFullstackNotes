The Problem

Exact Hashing Can't Answer "How Close Are These Two?"

Cryptographic hashes (MD5 / SHA-256) are built for the avalanche effect: 1 input bit flips → ~50% of output bits flip. Great for integrity checks. Fatal for similarity.

What we need: a fixed-size fingerprint where bit-distance ≈ content-distance. That's Locality-Sensitive Hashing (LSH) — SimHash is Google's famous implementation, by Moses Charikar.

Scenario 1 — Feature Extraction

Don't Hash the Document. Hash Its Shingles.

"the cat sat on the mat"

↓ split into overlapping word shingles (n=3), weight = frequency
"the cat sat"
"cat sat on"
"sat on the"
"on the mat"

Each shingle → its own 64-bit MurmurHash3 value. This is what makes SimHash order-aware when unigrams alone would not be.

Trap #1 — Bag-of-Words Blindness

"Dog Bites Man" ≠ "Man Bites Dog" — But Unigrams Say They Do

"dog bites man"

features (unigram): {dog, bites, man}

"man bites dog"

features (unigram): {dog, bites, man}

IDENTICAL FEATURE SET

Hamming distance = 0 → SimHash reports "certain duplicate," meaning is inverted.

Fix: use word-level shingles (n≥3) instead of single words. "dog bites man" and "man bites dog" then produce entirely different features — fingerprints diverge sharply.

Trap #2 — Threshold Ambiguity

Right at the Cutoff, SimHash Guesses Wrong Both Ways

3 (threshold)

False positive: two different articles both quoting the same 200-word press release → land at distance 2–3 → wrongly merged.

False negative: two near-identical articles, one with 200 extra words of nav/ad boilerplate → land at distance 6–8 → wrongly kept distinct.

Mitigation: strip boilerplate before feature extraction. Never auto-merge on SimHash alone — treat it as a candidate generator, verify top candidates with exact Jaccard similarity on shingle sets before acting.

Cheat Sheet

Decision Tree + The Exact Interview Line

USE billions of docs · lexical near-dupes · fixed-size fingerprint needed · crawler dedup, plagiarism, spam clustering, log dedup

SKIP need semantic similarity (→ embeddings+ANN) · corpus is small (→ direct Jaccard/edit-distance) · need exact-match guarantees (→ SHA-256)

"SimHash is a candidate generator, not a verdict... never auto-reject on SimHash alone — any submission whose fingerprint lands within the threshold gets flagged and passed through a cheaper-than-full-text-diff but more precise second check, like Jaccard similarity over the actual shingle sets... before it's surfaced to a moderator or auto-blocked."

— Interview answer, 50M posts / 100K submissions per day scenario
