A MySQL request: 1ms network + 5–10ms disk read + 1ms network = ~10ms total. Actual CPU work: 0.002ms (0.02%). Threads sleep 99.98% of the time — that's why you need 500 threads for 500 concurrent requests.

The Solution — Pure RAM

RAM access: 100 nanoseconds. Disk access: 5,000,000 nanoseconds (5ms). Redis is 100,000× faster per operation — there's nothing to sleep on, so one thread is enough.

epoll — One Thread, 10,000 Sockets

The Secret Weapon

One thread calls epoll_wait() — OS blocks until ANY socket has data, then returns the ready list in one wake-up. No thread-per-connection, no context switches, no 10GB of RAM for 10,000 thread stacks.

More Threads Would Hurt Redis

Trap — Mutex Overhead > The Work Itself

lock: 50ns
SET: 100ns

Single-thread: 100ns work + 0ns lock = 100ns/op. Multi-thread: 100ns + 50ns lock = 150ns/op — 50% SLOWER. Amdahl's Law: 0% of command execution is parallelizable.

Why INCR Never Races

page_views = 99 → ?

✕ Two threads: A reads 99, B reads 99 (before A writes), A writes 100, B writes 100 — lost an increment, should be 101.

✓ Single thread: reads 99 → writes 100 → next INCR reads 100 → writes 101. Correct, every time, zero locks. This is why INCR/SETNX/ZADD are atomic by default.

Redis 6: I/O Threads, Not Execution Threads

What's Actually Multi-Threaded

→

Before Redis 6, socket I/O ate 30% of the thread at 1M ops/sec. Redis 6 added optional io-threads for reading/writing raw bytes — command execution stays single-threaded. Background threads (BGSAVE fork, AOF rewrite, lazy-free UNLINK) never touch the main hash table either.

Decision Tree & Interview Answer

Quick Reference

Need atomic counters/locks? → single-thread guarantees it free (INCR/SETNX). Socket I/O bottlenecked at 1M+ ops/sec? → enable io-threads. Need more raw throughput? → Redis Cluster, not more threads per node.

"Redis is fast because 100ns RAM operations don't need threads — one event loop with epoll processes 10,000 connections without sleeping, and single-threaded execution eliminates lock overhead that would cost more than the operations themselves."
