Deep Dive — Trap

Key rotation without a grace period

kid: key-2024-08
kid: key-2024-05

JWKS endpoint must publish both old and new signing keys during rotation.

Delete the old key too early → tokens signed 2 minutes before rotation fail verification everywhere, instantly.

JWKS cache TTL on verifying services: commonly 10–60 min. Keep old keys published at least that long.

Scenario

RBAC vs. ABAC

RBAC = role lookup
ABAC = policy engine

RBAC: user.roles.contains("admin") OR ("owner") → O(1) table lookup, embedded in the JWT.

ABAC: department match AND business hours AND corporate IP → evaluated by a policy engine (e.g. Open Policy Agent).

ABAC is more flexible, but harder to audit — "why was this allowed" is no longer a simple lookup.

Interview Answer

The decision tree

20 microservices — avoid hitting a central auth server every request?
→ Short-lived, RS256-signed JWT. Verify locally via cached JWKS public key.
Need to revoke a compromised user fast?
→ Short access-token TTL (~10min) + refresh token checked server-side, with reuse detection → revoke the whole token family on theft signal.
Need finer-grained, changing rules?
→ Keep roles in the JWT for RBAC. Push ABAC-style rules to a policy engine, not the token.
"So the worst-case exposure window for a compromised access token is capped at its own short TTL, while the refresh flow gives me a real revocation point without making every request hit the database."
