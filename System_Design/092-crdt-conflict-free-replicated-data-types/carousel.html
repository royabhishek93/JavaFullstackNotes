CRDTs: Conflict-Free Replicated Data Types

Invisible "tombstone" nodes can hide inside a 10,000-character document after 50,000 keystrokes — dead, but still eating memory and still transmitted on every sync. Merge two offline replicas with zero server, zero locking — if you get the data structure right.

Merge must be commutative, associative, idempotent — order and repeats never matter.

G-Counter (Grow-Only Counter)

Simplest CRDT

{A:1}
{B:3}
{C:1}

Each replica writes ONLY its own slot. merge(s1,s2) = elementwise max().

Converged state: {A:1, B:3, C:1} → total = 5 likes

Why Not a Shared Counter?

The Race Condition Trap

+1
✕

Two replicas incrementing the SAME shared integer concurrently = lost-update race condition across a network partition.

✓ Fix: per-replica slots (G-Counter) sidestep the race entirely — no locks, no CAS, no coordinator.

Every char: (replicaId, logicalClock, parentRef). Concurrent inserts after 'A' tie-break by higher clock wins → deterministic order on every replica, no coordination: "AXYB"

Tombstones — The Real Cost

Trap: Metadata Growth

X(R1,3)
DELETED
→
hidden from user

Deletes are flagged, never removed — a concurrent remote insert may still reference the node. 10K-char doc, 50K keystrokes → 40,000+ tombstoned nodes, ~33+ bytes/char overhead.

Fix: GC once version vectors prove ALL replicas saw the tombstone (Yjs, Automerge).

CvRDT vs CmRDT

State-Based vs Operation-Based

CvRDT
ships full state
CmRDT
ships single ops

CvRDT 50-150KB per sync for a 5K-char doc — simple, but bandwidth-heavy if done every keystroke.

CmRDT 40-60 bytes/op — lean, but needs guaranteed at-least-once delivery or an edit silently vanishes.

Production systems (Automerge, Yjs) are hybrid: ops for live sync, state snapshots for bootstrap + GC.

Real World

Figma + Indian Scale

Figma: custom CRDT-like canvas — shapes merge as independent last-writer-wins fields per property, not one linear sequence. "CRDT" is a family of techniques, not one algorithm.

Swiggy: delivery-partner status updates in low-network zones merge as additive facts, so a delivered order never flips back to "in transit."

Zomato / PhonePe: concurrent menu edits and multi-device transaction history dedupe cleanly on reconnect — same G-Counter/RGA pattern, different payload.

Decision Tree & Interview Answer

Quick Reference

Extended offline editing + no mandatory server? → CRDT. Always-reachable server? → OT is simpler. Need strong (not eventual) consistency — e.g. a bank balance? → Skip CRDTs entirely.

"The moment 'no server available to referee in real time' is a hard requirement, Operational Transformation is off the table — OT fundamentally needs a central authority to transform incoming operations against everything it's already committed. CRDTs solve the same convergence problem without that requirement, because the merge logic lives inside the data structure itself rather than in a coordinating service."
