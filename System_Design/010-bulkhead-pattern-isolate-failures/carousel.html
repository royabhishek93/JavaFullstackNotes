Thread Pool Isolation

Type 1 — Most Common

Each service gets a dedicated thread pool. Full pool → new requests rejected immediately, not queued.

Best for: blocking I/O (HTTP calls, DB queries)

Semaphore Isolation

Type 2 — Lightweight

A counting semaphore limits concurrent calls — no separate threads spun up.

Best for: async/reactive code (WebFlux). ✕ Weaker protection against thread exhaustion.

Sizing Formula

Don't Guess

pool_size = (req/sec × avg_latency_sec) × 1.2

Payment: 500 req/s × 0.2s × 1.2 = 120 threads

Recommendations: 200 req/s × 0.1s × 1.2 = 24 threads (small on purpose — degrade fast)

Keep Queues Small

The Trap

✕ Large queue "to be safe" just delays failure and hides the real problem.

✓ Queue capacity 5-10 or zero — reject fast, return a fallback immediately.

Decision Tree & Interview Answer

Quick Reference

Blocking I/O call? → Thread pool bulkhead. Async/reactive? → Semaphore bulkhead. Either way → pair with circuit breaker + timeout.
