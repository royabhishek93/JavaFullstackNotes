Decoding a Real ID

Extract Timestamp, Worker, Sequence

timestamp = (id >> 22) + EPOCH

workerId = (id >> 12) & 0x3FF

sequence = id & 0xFFF

Result: "1st ID minted at 2023-10-19T08:44:20Z by worker #1"

Throughput

Real Numbers

4096 IDs/ms/worker × 1000ms = ~4.1M IDs/sec per worker

× 1024 workers = ~4.2 BILLION IDs/sec theoretical system ceiling

Clock Drift

The #1 Production Trap

NTP corrects clock backward → risk of a duplicate ID if you naively use current time.

Fix: REJECT (throw, force retry) or WAIT (spin until clock catches up) — never silently reuse a (timestamp, sequence) pair.

Sequence Exhaustion

>4096 Requests in 1ms

Sequence hits 4096 → overflow → generator busy-waits until the clock ticks to the next millisecond, then resets sequence to 0.

Decision Tree & Interview Answer

Quick Reference

Sharding across many nodes, need time-sortable keys? → Snowflake. Security-sensitive public ID? → UUIDv4 instead (reveals nothing).

"Snowflake fixes both problems UUIDs have: it's 64 bits instead of 128, and because the timestamp occupies the highest bits, IDs generated later are numerically larger — as a primary key, new rows insert at the tail of the B-tree instead of scattering randomly."
