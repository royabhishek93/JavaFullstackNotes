One local single-DB transaction writes the order + an outbox event. No distributed lock, no coordinator crash risk. If the debit fails, a compensating WalletDebitFailed event cancels the order.

Decision Tree & Interview Answer

Quick Reference

2-3 DBs, coordinator highly available, latency acceptable (banking/ERP)? → 2PC/XA is fine. Microservices, >10K TPS, or DBs without XA support (DynamoDB, Cassandra)? → Saga with compensating transactions.

"2PC guarantees atomicity across multiple databases but has a blocking failure mode: if the coordinator crashes between PREPARE and COMMIT, all participants hold locks indefinitely. For microservices, I use Saga with compensating transactions instead — eventual consistency, but no distributed locks."
