Virtual Nodes

Keeping Load Proportional

Each physical shard gets many ring positions (Cassandra default: 150 vnodes per node).

A high-capacity node gets more vnodes → more of the ring → proportionally more load, even if the physical node itself sits in an unlucky part of the ring.

Choosing a Shard Key

4 Required Criteria

✓ High cardinality — not country_code (only ~200 values)

✓ Even distribution — not skewed by a few huge tenants

✓ Present in most queries — avoids scatter-gather

✓ Immutable — not email (mutable = row must migrate on change)

Cross-Shard JOINs Don't Work

The Trap

Users on Shard 1, Orders on Shard 3 — no SQL JOIN across shards.

Fixes: co-locate related tables by the same key, application-level join (expensive), or denormalize (embed the join data — the production pattern at scale).

Decision Tree & Interview Answer

Quick Reference

Need range queries? → Range sharding. Fixed cluster size forever? → Hash sharding. Cluster size will change? → Consistent hashing.
