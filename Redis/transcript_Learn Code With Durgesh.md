## Scenario-Based Questions

1. **A delivery app updates a rider's GPS coordinates every second while the trip is active, but the final route only needs to be looked up occasionally afterward. Why is it wasteful to write every coordinate straight into PostgreSQL, and what is a better split?**
   Writing every second directly to a disk-backed database multiplies read/write load and can degrade performance under many concurrent trips. Store the live coordinates in Redis (in-memory, fast) while the trip is active, and once the trip ends, persist only the final computed path (or route summary) into the permanent database.

2. **A social app must show "you have 12 unread messages" instantly on every page load. Why is it better to keep a Redis counter than to run a `COUNT(*)` query against the messages table each time?**
   The count is a *computed* value; recomputing it by scanning/joining tables on every page load repeats expensive work. Caching the number in Redis and incrementing/decrementing it as messages arrive or are read avoids repeated computation and keeps the UI fast.

3. **In the Redis client-server (master-slave-style) architecture, a Spring Boot application needs to read and write cache data. What role does the Spring Boot app play, and what actually executes the commands?**
   The Spring Boot application acts as a client, exactly like the `redis-cli`. It sends commands/queries to the Redis server, which is the master that stores and processes all the data; the client only sends requests and receives responses.

4. **You installed Redis with a package manager (like snap) for a quick demo, but now you need to fully customize `redis.conf` for a production-like setup. What should you do differently?**
   Package-manager installs (especially sandboxed ones) may not expose full control over the configuration file. For full control, install Redis standalone from source/official binaries (or run it in a container you manage) so the config file is directly editable.

5. **You need to track millions of unique IP addresses hitting an API, but only care about set-membership checks (has this IP been seen before), not ordering. Which data type fits, and why not a List?**
   A Set. It stores unique, unordered strings and gives fast membership checks; a List would allow duplicates and preserve insertion order, which is unnecessary overhead for this use case.

6. **A gaming app needs a live leaderboard where players are automatically re-ranked whenever their score changes.** Which Redis data type is designed exactly for this, and what is stored alongside each member?**
   A Sorted Set. Each member is stored with an associated numeric score, and Redis automatically maintains the members in score order, so ranking updates are automatic on every score change.

7. **You need to represent a user profile (name, phone, etc.) as a single logical object in Redis rather than several separate keys.** Which data type is "ideal for representing objects," and what commands let you read/update one field at a time?**
   A Hash. `HSET`/`HGET` let you set or read individual field/value pairs within the same key, and `HGETALL` returns every field at once, without needing a separate key per field.

8. **A permissions system needs to check and flip individual boolean flags (like feature access bits) for millions of users as compactly as possible.** Which Redis data type is built for bit-level operations, and what underlying type does it use?**
   A Bitmap. It manipulates individual bits within a Redis string, allowing very compact storage and fast bit-level get/set operations compared to storing each flag as a separate key.

9. **An analytics dashboard needs an approximate count of unique daily visitors across millions of events, and exact precision is not required, but memory must stay very low.** Which Redis data type is purpose-built for this trade-off?**
   HyperLogLog. It is a probabilistic data structure for counting unique elements using a small, fixed amount of memory, at the cost of being approximate rather than exact.

10. **A food delivery app needs to find all restaurants within a given radius of a customer's coordinates.** Which Redis feature directly supports storing coordinates and performing radius-based queries?**
    Geospatial indexes, which store latitude/longitude pairs and support radius and bounding-box queries directly, without you needing to implement distance math in the application layer.

11. **A background job system needs to record events in the exact order they occur and let multiple worker processes consume them for processing, similar to a message log.** Which Redis data type fits, and how is it different from a List?**
    A Redis Stream. It behaves like an append-only log purpose-built for event ordering and multi-consumer processing (with consumer groups), which a plain List does not provide out of the box.

12. **A production system cannot tolerate losing all cached data if one Redis node crashes unexpectedly.** What Redis feature addresses this, and how does it work at a high level?**
    Master-slave replication. Data written to the master is replicated to one or more replica nodes, so if the master fails, a replica holding the same data can take over, preventing total data loss from a single node failure.
